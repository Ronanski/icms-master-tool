# Basahin muna (user rule)

Bago ang anumang sagot o pagbabago: basahin MUNA ang `HANDOFF.md` (iisang file ng estado, threads, utos ng user at style; sapat na ang repo para magpatuloy ang kahit sinong Claude o account), saka ang `docs/SPEC.md` (ang gusto ng user) at `PROJECT_RULES.md`. Bagong account o bagong project: sundin muna ang `docs/handoff/NEW_ACCOUNT_SETUP.md` bahagi B. Bawat thread: basahin ang sariling seksyon sa `docs/handoff/THREAD_BRIEFS.md`, lalo na pagkatapos ng compact.

**I-update ang `HANDOFF.md` sa katapusan ng BAWAT gawain** (bawat thread / session, kasama sa parehong PR o Beta): estado, kalagayan ng thread, bukas na isyu, at bawat bagong utos o desisyon ng user (paraan: `HANDOFF.md` seksyon 8). Ang alaala ng project ay ang file na iyon, hindi ang memory ng isang session. Tingnan muna ang tunay na estado ng repo (git log, files); huwag sumagot mula sa alaala. Pinaikli 2026-10-26 (pinayagan ng user para makatipid at bumilis); ang lumang bersyon ay nasa git history.

## App sa isang tingin
- **ABC** = analog logic, **DITL** = digital logic; iisang mundo, laging magkakabit.
- **VIEW** = tingin at trace lang; **RUN / SIMULATE** = force, A / M / R, SV, MV. Hiwalay ang dalawa.
- **Plant model OFF** = ang user ang naglalagay ng value; **ON** = physics + steam table.
- Starting point: 150 MW at Cold. Training: Cold → 150 MW lang. Detalye at kulang: `docs/SPEC.md`.

## HINDI NAGBABAGO NA KAALAMAN (user, 2026-10-15) — basahin bago ang bawat sagot

Ang kaalaman na ito ay galing sa user at sa repo. Kapag nawala ito sa isip ng isang session, ang file na ito ang alaala. Ang bawat sagot ay dapat sumunod dito.

1. **Ang tag ay iisang signal sa buong DCS.** Ang `FICFA1071.REM`, `.LOC`, `.MAN`, `M.xxxx`, `B.xxxx`, `AIxxxx`, `SIxxxx` na lumalabas sa maraming sheet ay ISANG address lang. Kapag may input na may tag, KAKABIT iyon: sa HMI button, sa output ng ibang sheet, sa I/O list o memory list. Hindi ito "patay na input". Kapag hindi nakakabit, bug ng app iyon (link, tag reader) at inaayos, hindi ito iniulat bilang "needs verification".
2. **Ang .MAN / .LOC / .REM ay ESTADO ng mode** ng controller o ng MAN station (textbook: status word .MAN = MANUAL, .LOC = LOCAL, .REM = REMOTE; ABC-010 "DRUM LEVEL CONTROL MANUAL FOR START-UP  LICBR1001B.MAN"). Ang pindot ng M / A / R ay nagse-set nito at NANANATILI hanggang pindutin ang ibang mode (1.22.0; dati ay pulse, interpretasyon ng naunang session, hindi ng user). Ang R / A / M sa faceplate ay pumipindot ng mga address na ito sa LAHAT ng sheet na gumagamit ng tag (`src/ui/hmi/hmi.js`: `modeNetsByTag`). Ang SV LOCAL / REMOTE ay umaandar lang kapag nakakabit ang mga address na ito sa logic.
3. **Ang logic ang nagsasabi ng scenario at proseso.** Ang kailangang estado ng input para maging 1 o 0 ang isang net (force manual, interlock, permissive) ay BINABASA mula sa netlist (gate, comparator, FF, timer, selector, link), hindi hinuhulaan ng random na test. Mga halimbawa na nasuri na: TICHR1002 (M.0172 = temperatura > saturation + 11 °C), PICAS1005 (M.0129: FF ng TICR1004.PV < 230 / > 235 at PICR1003.PV < 9.5 / > 11.5), HS-COAL (lahat ng feeder at mill ay tumatakbo), PICFG108 (MV < 14 % = force manual: itaas muna ang MV).
4. **Ang mga ito ay nasa repo na (`document-references/`):** analog at digital diagram (PDF/DWG), I/O list, memory list 101~105, PID / MAN / SUMA parameters, linear curves, drum level at flow compensation, HMI snapshot ng control room, textbook, legends. Ang HMI graphics ay nagsasabi ng flow, lokasyon ng valve, damper at motor, at ng tugon ng PV. HINDI kailangan ng P&ID. Walang tanong sa user na masasagot ng mga ito.
   - (user, 2026-10-16) Dagdag: operating procedure ng planta: `procedure-start-up-PR-OPE-5002-02.docx` (start-up, sunod-sunod na hakbang), `procedure-normal-shutdown-PR-OPE-5003-01.docx`, `procedure-shutdown-to-bottle-up-PR-OPE-5004-01.docx` (ito ang batayan ng plant scenario: start-up / shutdown / load / trip, kasama ang normal / alarm / trip na limit). PLC logic ng mga subsystem: `sand-sootblower-logic.zip` (sand silo 770 ~ 777 + sootblower DITL-80x, DWG + PDF), `bottomash-limestone-logic.zip` (bottom ash HD600 BA-01 ~ 58 at conveyors BA-59 ~ 74, DWG + PDF; limestone `limestone_logic.xls`). `dcs-hardware-wiring.zip` = system, PDP, SER, ARP / IRP, MPL, FCS wiring.

10. **BU-CMD = protection (user, 2026-10-17).** Ang BU-CMD (back-up command) ay block command, kadalasan output ng digital logic. Kapag nag-BU-CMD ang isang MAN station (hal. ABC-001C HIC-BM M.2013 = steam flow < 220 T/H, HP bypass bukas, turbine trip, SIG.AB), ang station ay MANUAL (`.MAN` = 1, para malaman ng ibang logic: tracking ng PIC-COBM, CCS / boiler follow mode), HAWAK ang MV (walang talon), at hindi kusang bumabalik sa AUTO: ang operator ang pumipindot ng A (PR-OPE-5002 "Put Boiler Master to Auto"). Ang textbook ay may hiwalay na status bit na `.BUP` (BACK UP); ang `.MAN` ang ginagamit dahil iyon ang binabasa ng drawing.
